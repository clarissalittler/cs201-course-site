Lesson 5: Writing Functions

Functions in Assembly

In C, functions are a fundamental abstraction. In assembly, there is no built-in concept of a "function" — just labels you can jump to. What makes a label into a function is convention: the calling convention defines how arguments are passed, where the return value goes, and which registers must be preserved. On Linux x86-64, this is the System V AMD64 ABI.

call and ret

Two instructions provide the mechanism for function calls:

  • call label — Pushes the address of the next instruction (the return address) onto the stack, then jumps to label. Conceptually: push [return address]; jmp label (note: push %rip is not an actual valid instruction — the hardware does this internally)
  • ret — Pops the return address from the stack and jumps to it. Conceptually: pop [into %rip] (again, pop %rip is not a valid instruction — the hardware does this internally)

The Calling Convention

The System V AMD64 ABI defines three key rules:

1. Argument Passing

The first six integer/pointer arguments are passed in registers, in this order:

Argument #Register
1st%rdi
2nd%rsi
3rd%rdx
4th%rcx
5th%r8
6th%r9

Arguments beyond the sixth are pushed onto the stack (right to left). The return value is placed in %rax.

2. Callee-Saved Registers

The called function must preserve these registers — if it uses them, it must save and restore their original values:

%rbx, %rbp, %r12, %r13, %r14, %r15

3. Caller-Saved Registers

All other registers may be clobbered by the called function. If the caller needs their values after the call, it must save them itself (typically by pushing them onto the stack before the call):

%rax, %rcx, %rdx, %rsi, %rdi, %r8, %r9, %r10, %r11

Hand-Write: A Simple Function

Let's write a function add_nums that takes two arguments and returns their sum:

        .text
        .global _start

# Function: add_nums(a, b) -> a + b
add_nums:
        push %rbp              # save old base pointer
        mov %rsp, %rbp         # set up new base pointer
        mov %rdi, %rax         # %rax = first arg (a)
        add %rsi, %rax         # %rax = a + b (return value)
        pop %rbp               # restore base pointer
        ret

_start:
        mov $17, %rdi          # first argument
        mov $25, %rsi          # second argument
        call add_nums          # result in %rax

        mov %rax, %rdi         # exit with result
        mov $60, %rax
        syscall
$ echo $?
42

The push %rbp / mov %rsp, %rbp at the start and pop %rbp / ret at the end form the prologue and epilogue. For a function this simple, the prologue is not strictly necessary, but it is the standard pattern.

Function Calls Versus Syscalls

A normal function call and a Linux syscall are related but not identical interfaces. The call instruction follows the System V AMD64 function calling convention. The syscall instruction follows the Linux kernel's syscall convention.

InterfaceArgument registersReturn registerImportant clobbers
Function call%rdi, %rsi, %rdx, %rcx, %r8, %r9%raxcaller-saved registers may be overwritten
Syscall%rdi, %rsi, %rdx, %r10, %r8, %r9%rax%rcx, %r11

For read and write, only the first three arguments are used, so the two conventions line up nicely. That makes them perfect first examples of assembly wrapper functions. If you later wrap a syscall with four or more arguments, you must remember to move the fourth argument from %rcx into %r10 before executing syscall.

Hand-Write: Reusable read / write Wrappers

We can package bare syscalls inside ordinary assembly functions. The caller uses call with the normal function convention; the wrapper translates that request into a kernel syscall. In this example, we also use a branch to avoid writing anything when read returns EOF or an error.

        .section .rodata
prompt: .asciz "Type a line: "
plen = . - prompt - 1

        .section .bss
buffer: .skip 64

        .text
        .global _start

# write_buf(fd, buf, count) -> bytes written or negative error code
write_buf:
        mov $1, %rax
        syscall
        ret

# read_buf(fd, buf, count) -> bytes read or negative error code
read_buf:
        mov $0, %rax
        syscall
        ret

_start:
        mov $1, %rdi
        lea prompt(%rip), %rsi
        mov $plen, %rdx
        call write_buf

        mov $0, %rdi
        lea buffer(%rip), %rsi
        mov $64, %rdx
        call read_buf

        cmp $0, %rax
        jle done               # 0 = EOF, negative = error

        mov %rax, %rdx
        mov $1, %rdi
        lea buffer(%rip), %rsi
        call write_buf

done:
        mov $60, %rax
        xor %rdi, %rdi
        syscall
$ ./echo_line
Type a line: hello, syscalls
hello, syscalls

Key points in this program:

  • write_buf and read_buf are leaf functions: they do not call any other functions, so they need no stack frame here.
  • The caller passes (fd, buf, count) in %rdi, %rsi, and %rdx. The wrappers only need to place the syscall number in %rax.
  • read_buf returns the number of bytes read in %rax, just like the raw syscall. The caller then moves that value to %rdx before calling write_buf.
  • syscall clobbers %rcx and %r11. That is fine here because both are caller-saved registers anyway.

Hand-Write: Recursive Fibonacci

Recursion is the real test of understanding functions, because each call creates a new stack frame. Here is recursive Fibonacci:

        .text
        .global _start

# fib(n): returns the nth Fibonacci number
# fib(0) = 0, fib(1) = 1, fib(n) = fib(n-1) + fib(n-2)
fib:
        push %rbp
        mov %rsp, %rbp
        push %rbx              # save callee-saved register

        cmp $1, %rdi           # base case: n <= 1
        jle fib_base

        # Recursive case
        mov %rdi, %rbx         # save n in callee-saved %rbx
        dec %rdi               # n - 1
        call fib               # fib(n-1), result in %rax
        push %rax              # save fib(n-1) on stack

        lea -2(%rbx), %rdi     # n - 2
        call fib               # fib(n-2), result in %rax

        pop %rcx               # restore fib(n-1)
        add %rcx, %rax         # %rax = fib(n-1) + fib(n-2)
        jmp fib_done

fib_base:
        mov %rdi, %rax         # return n (0 or 1)

fib_done:
        pop %rbx               # restore callee-saved register
        pop %rbp
        ret

_start:
        mov $10, %rdi          # compute fib(10)
        call fib
        mov %rax, %rdi         # exit with result
        mov $60, %rax
        syscall
$ echo $?
55

Key points in this program:

  • %rbx is callee-saved, so fib pushes and pops it. We use %rbx to hold n across the recursive calls because we know fib won't clobber it.
  • We save fib(n-1) on the stack before calling fib(n-2) because %rax is caller-saved and will be overwritten by the second call.
  • Each recursive call creates a new stack frame. For fib(10), there will be many nested frames on the stack simultaneously.

gcc Comparison: Function Compilation

The C equivalent:

int add_numbers(int a, int b) {
    int sum = a + b;
    return sum;
}

Compiled with gcc -Og -S:

add_numbers:
        leal    (%rdi,%rsi), %eax
        ret

gcc uses lea to compute a + b directly into %eax (the 32-bit return register). No prologue or epilogue — this is a leaf function (it doesn't call other functions) and doesn't need stack space, so gcc optimizes away the frame setup entirely.
