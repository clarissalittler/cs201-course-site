## Most consequential corrections

1. **Reader–writer example used a mutex with the wrong ownership model (Module 6, Lesson 6).** The first reader locked `write_lock`, but the last reader could be a different thread. Unlocking another thread's default mutex is undefined behavior. The resource gate is now a binary semaphore, while a mutex still protects the reader count. The example retries interrupted semaphore waits, checks thread creation/join results, and destroys its synchronization objects. Reader preference and its starvation limitation remain explicit. Sources: [POSIX mutex ownership](https://man7.org/linux/man-pages/man3/pthread_mutex_lock.3p.html), [semaphore wait semantics](https://man7.org/linux/man-pages/man3/sem_wait.3.html).

2. **Posit overflow was incorrectly described as NaR (Module 2, Lesson 6).** Finite out-of-range results saturate to signed maxPos; tiny nonzero results round to signed minPos. NaR represents results without a uniquely defined real value. Also removed the misleading claim that the regime gives smooth scaling near zero. Source: [Posit Standard (2022), section 4](https://posithub.org/docs/posit_standard-2.pdf).

3. **COMMON storage was conflated with ELF weak binding (Module 9, Lesson 2; heap/linking reference; practice question).** `.comm` and `-fcommon` create COMMON symbols, not weak symbols. Explicit weak definitions have different resolution rules; “choose the largest” describes COMMON allocation. The revised lesson distinguishes all three cases and retains the GCC 10 `-fno-common` note. Sources: [GAS `.comm`](https://sourceware.org/binutils/docs/as/Comm.html), [GAS `.weak`](https://sourceware.org/binutils/docs/as/Weak.html).

4. **GDB label names were said to require `-g` (Module 3, Lesson 10; practice question).** Ordinary symbol names can remain without source-line debug information. The question now asks about missing assembly source lines. Source: [GDB symbol information](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Symbols.html). Confirmed locally with an executable assembled without `-g`.

## Other corrections by topic

- **C and representation:** corrected pass-by-value explanations, including array-to-pointer conversion; distinguished `printf` and `scanf` floating-point formats; checked the sample input result; qualified `const` array bounds and C23 boolean names; narrowed `void *` conversion to object pointers. Separated pointer width, architectural word terminology, virtual address space, and physical RAM, including the 32-bit PAE counterexample. Corrected the reference's claim that bitwise AND of pointers compiles and its missing negative-left-shift restriction. Sources: [WG14 C23 draft](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf), [Linux high memory documentation](https://www.kernel.org/doc/html/v6.10/mm/highmem.html).
- **Floating point:** an exactly representable double-to-float conversion does not lose accuracy; subnormal results begin below the smallest normal value, not only below the smallest subnormal. Distinguished IEEE conversion behavior from core C guarantees and removed the universal floating-point speed claim. See the WG14 draft above, especially conversion and Annex F rules.
- **Assembly:** `SETcc` also accepts a byte in memory; `UCOMISD/UCOMISS` clear OF, SF, and AF rather than leaving those flags untouched. Both points were exercised locally. The three loop forms are equivalent only within the stated positive, non-overflowing input domain. The symbol-table example now defines an actual label rather than treating `.global` as a definition.
- **Course I/O helpers:** compared the lesson's description with `cs201/fall2026/lecture6/readInt.s` and `writeInt.s`. The local reader assumes nonempty nonnegative decimal input delivered in one newline-terminated read and does not validate arbitrary input. The local writer does not append a newline. The lesson now states these limits. The helper sources themselves were not changed; the copies downloadable from D2L were not verified.
- **Signals:** synchronous does not mean repeatable across runs—page residency can change whether a load faults. Distinguished `WNOHANG`'s zero result from `ECHILD`; made the SIGCHLD loops retry `EINTR`; qualified `SA_RESTART`. Sources: [wait/waitpid](https://man7.org/linux/man-pages/man2/waitpid.2.html), [Linux signal interfaces](https://man7.org/linux/man-pages/man7/signal.7.html).
- **Concurrency:** atomicity is indivisibility relative to other threads, not immunity from interruption. The entire condition-variable wait/reacquisition sequence is not one atomic action. Also clarified why `-lpthread` is not a general substitute for `-pthread`. Source: [POSIX condition waits](https://pubs.opengroup.org/onlinepubs/9799919799/functions/pthread_cond_clockwait.html).
- **I/O and TCP:** successful `fgets` termination is different from EOF/error behavior. Successful socket output is not acknowledgment that the peer application processed it, and a TCP checksum is not cryptographic integrity. Sources: [C draft, fgets](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf), [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html), [send](https://www.man7.org/linux/man-pages/man2/send.2.html).
- **Performance:** removed the claim that DRAM is literally getting slower and that an array-traversal speed difference is entirely cache behavior. GCC 12+ already enables vectorization at `-O2`; `-O3` uses a more permissive cost model. Source: [GCC optimization options](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html).
- **Kernel organization:** `swapgs` does not itself change the stack pointer. Linux 6.12 x86-64 uses generated switch dispatch, so the literal function-pointer-table description was revised. Marked the two-crossing file-read comparison as a simplified model; qualified container PID visibility and CHERI's hybrid/pure-capability distinction; clarified user-space synchronization fast paths. Sources: [Linux entry assembly](https://raw.githubusercontent.com/torvalds/linux/v6.12/arch/x86/entry/entry_64.S), [Linux syscall dispatch](https://raw.githubusercontent.com/torvalds/linux/v6.12/arch/x86/entry/syscall_64.c), [PID namespaces](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html), [CHERI programming guide](https://www.cl.cam.ac.uk/techreports/UCAM-CL-TR-947.pdf), [kernel futex documentation](https://www.kernel.org/doc/html/latest/locking/pi-futex.html).
