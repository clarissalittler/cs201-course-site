Lesson 2: Bits, Bytes, and Data Sizes

Information Storage

In this summary we will be covering the binary representation of data within a computer system. Data includes numbers, symbols (letters, digits, etc), graphics, audio, and other data. Throughout this course, we will concentrate on numeric data.

No matter what type of data, all data is represented by binary digits or bits. A bit can be one of two values: 0 or 1. Bits are stored in memory in a sequence of cells. Each 8 cells (1 byte) is addressable as a whole by the system. Therefore, the smallest unit of addressable memory is one byte (8 bits).

With the exception of one-byte data values, data is stored across multiple cells. We will talk about how this is done in the lecture on byte ordering.

The bit pattern is the series of bits across many cells that represent one data value. Since a user is not likely to know binary, this bit pattern will need to be translated into the actual value (numbers, letters, etc) that the user can understand. This is typically done in hardware.

Word and Data Sizes

The word size describes an architecture's natural unit of integer processing; terminology varies (x86 instruction names still use "word" for 16 bits). On the Linux x86-64 LP64 platform used in this course, general-purpose registers and pointers are 64 bits wide. Pointer width, virtual address width, and physical address width are related but distinct. A 32-bit byte address can name 232 bytes (4 GiB) in one address space, but a 32-bit x86 system with Physical Address Extension (PAE) can have more physical RAM. A full 64-bit byte address could name 264 bytes (16 EiB); actual x86-64 hardware and operating systems implement smaller address ranges.

Do not infer the size of int from register or pointer width: on our LP64 platform, int is 32 bits while long and pointers are 64 bits.

In C/C++ languages, all simple or primitive data types have a fixed size associated with them. Sizes depend on the implementation and its data model, not just the architecture's word size.

Datatypes like int can be different byte lengths on different architectures, and the sizeof() operator can be used to compensate for that:

int a[100];
int n_elements = sizeof(a) / sizeof(int);

Below is a table of the most common data types and their sizes for the 64-bit architecture (this is a portion of figure 2.3 in the textbook)

Type Size in Bytes
char (signedness is implementation-defined) 1
short 2
int 4
long 8 (4 on 64-bit Windows)

float 4

Some things to note: char * occupies 8 bytes in the LP64 data model used here. The sizes for int and long are not the same on all 64-bit systems. Linux and macOS use the LP64 data model where long is 8 bytes, but 64-bit Windows uses the LLP64 data model where long stays at 4 bytes (only long long and pointers grow to 8 bytes). When portability matters, use the explicit-width types from <stdint.h> (int32_t, int64_t, uint8_t, etc.).

There are signed and unsigned versions of integer numbers. The signed versions can represent both positive, zero, and negative. The unsigned versions can only represent positive and zero. They are typically the same size but have different ranges of values. We'll talk at length about signed and unsigned integer types later in this module (Lessons 7–11). Floating point number types (float and double) are always signed types. We'll talk about floating point representation in Module 2.
